# 01 · 快速开始

> 目标：从零到「看到第一张依赖图」，大约 5 分钟。

---

## 1. 安装 DepScan

### 方式 A：从 vsix 安装（推荐）

1. 打开 VS Code → 扩展面板 → 右上角 `...` → **从 VSIX 安装…**
2. 选择 `depscaner-win32-x64-0.1.1.vsix`（平台专用包；通用包叫 `depscaner-0.1.1.vsix`）
3. 重新加载窗口

> **不需要安装编译器或 Clang。** 分析引擎已随插件分发（`engines/<platform>-<arch>/depscan-core`），Windows / Linux / macOS 各自使用对应二进制。

### 方式 B：从源码运行

```bash
git clone <repo> && cd DepScan
npm install
npm run build:core     # 编译 C++ 引擎
npm run build          # 打包扩展与 Webview
```

然后在 VS Code 打开该目录，按 `F5` 启动扩展开发宿主。

### 方式 C：市场安装

扩展市场搜索 **DepScan**（发布后可用）。

## 2. 准备一个 C++ 项目

首次体验可以直接用仓库自带的示例：

```
samples/demo/          # 15 个文件，故意埋了循环依赖与分层违规（有 main，是个应用）
samples/libdemo/       # 5 个文件的小库，**故意没有 main**：用来看「库项目从哪读起」
```

## 3.（可选但强烈建议）生成 compile_commands.json

DepScan 有两种精度：

| 场景 | 精度 | 说明 |
| --- | --- | --- |
| 有 `compile_commands.json` | **精确** | include 搜索路径、宏定义都来自真实编译命令，`<>` 形式的系统头文件也能正确解析 |
| 没有 | **近似** | 用内置结构解析器，速度快、零配置，但可能漏报 / 误报 |

生成方式（按你的构建系统选一个）：

**CMake**

```bash
cmake -S . -B build -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
# 产物在 build/compile_commands.json，DepScan 会自动发现
```

**Makefile / Ninja**

```bash
bear -- make                                   # 推荐
ninja -t compdb cxx cc > compile_commands.json # 使用 Ninja 时
```

**Bazel**

```bash
bazel run @hedron_compile_commands//:refresh_all
```

**qmake（Qt 5.12+）**

```bash
qmake -compile-commands
```

**Xcode**

```bash
xcodebuild | xcpretty -r json-compilation-database
```

> 生成后放到项目根目录即可。放在别处时用 `depscan.compile.commandsPath` 指定。
> 也可以用命令面板的 `DepScan: 如何生成 compile_commands.json？` 随时查看本页摘要。

## 4. 首次索引

1. 用 VS Code **打开项目根文件夹**（必须是文件夹，不是单个文件）
2. 插件会自动在后台建立索引（默认 `depscan.index.onStartup = true`）
3. 观察进度：
   - **状态栏左下角**：`⟳ DepScan 42%`
   - **活动栏 DepScan 图标 → 索引状态**：进度、文件数、符号数、依赖数、精度等级
4. 索引在后台进行，不阻塞编辑；随时可用 `DepScan: 取消索引` 中断

手动重建：命令面板 → `DepScan: 重建索引（全量）`，或点击「索引状态」视图标题栏的 ⟳ 图标。

## 5. 看第一张图

在任意 `.cpp` / `.h` 文件上：

- **右键 → 查看依赖图**，或
- **命令面板 → `DepScan: 查看依赖图`**，或
- 光标放在某个函数里 → **`DepScan: 查看当前符号的依赖图`**

> 界面布局：左侧是 Canvas 依赖图（可拖动/缩放/平移），右侧上半是节点详情、下半是图例。

你会看到：

- **蓝色**节点 = 文件，**绿色** = 函数，**橙色** = 类，**紫色** = 枚举，**灰色** = 宏
- **虚线边** = 近似依赖，**实线边** = 精确依赖
- 默认以当前文件为中心，展开 **2 层**（可用 `k` 调整）

## 6. 不知道该读哪个文件？看阅读路线

依赖图告诉你「谁和谁有关」，但不会告诉你**从哪读起**。侧边栏 → **DepScan → 阅读路线**
给出的是一份**有序**的清单：从 `main` 出发，按调用关系一步步排下去。

- 点任意一步 → 跳源码；标题栏可切换**广度优先 / 深度优先**与**文件级 / 函数级**
- 库项目没有 `main`？把光标放到导出接口上，用「**从光标处开始读**」换起点
- 标 ⚠ 的步骤表示这个名字在项目里还有别的定义（按名字消解可能选错了），
  展开「候选」可以自己改 —— 顺序图错一条边，后面整条顺序都是错的

详见 [07-阅读路线](07-阅读路线.md)。

## 7. 三平台引擎说明

插件按 `process.platform + process.arch` 选择引擎：

| 平台 | 目录 | 文件名 |
| --- | --- | --- |
| Windows x64 | `engines/win32-x64/` | `depscan-core.exe` |
| Linux x64 | `engines/linux-x64/` | `depscan-core` |
| macOS Intel | `engines/darwin-x64/` | `depscan-core` |
| macOS Apple Silicon | `engines/darwin-arm64/` | `depscan-core` |

查找顺序：

1. 配置 `depscan.engine.path`（手动指定，优先级最高）
2. `engines/<platform>-<arch>/`
3. 开发态 `engine/build/bin/<Config>/`

引擎启动失败时，`DepScan` 输出通道（视图 → 输出 → DepScan）会打印完整路径与错误原因。

## 8. 常见问题（快速版）

**Q：状态栏一直显示 `DepScan` 没动静？**
打开输出通道看日志；通常是项目里没有可索引的 C/C++ 文件（检查 `depscan.files.include`）。

**Q：图是空的？**
先执行一次 `DepScan: 重建索引（全量）`。若仍为空，说明焦点文件在项目里没有任何依赖关系。

**Q：节点太多看不清？**
把 `k` 调小（1–2 层），或打开工具栏的「按目录聚类」，或在搜索框里搜具体名字。

**Q：精度显示「近似」，但我明明有 compile_commands.json？**
检查它是否在项目根、`build/`、`out/` 等常见位置；或直接设置 `depscan.compile.commandsPath`。

更多问题见 [04-解析与精度说明](04-解析与精度说明.md)。
